Three ideas, one site

01 · Paper over terminal

Two materials

Your current site is all terminal. The references are all paper: torn grids, tape, stickers, big type. v2 uses both. The terminal sits underneath as the base layer and paper is laid on top. Every transition comes from paper and terminal touching: a sheet tears, a page prints out, a screen shows through a gap.

02 · Stack, not world

Layers in depth

No open world and no driving around. The camera moves on one rail into the screen, through a stack of sheets. Each section is a stack frame named like a Java trace (at dk.Portfolio.projects()). Scroll, keys, the command line or your hand all step through the same stack.

03 · HTML first, 3D on top

Readable by Google

All text is real, server-rendered HTML. The WebGL layer is drawn behind and between the HTML and never contains content. That fixes the SEO gaps, keeps screen readers working, and gives a clean 2D fallback for weak phones and for reduced-motion users.

Six layers per sheet

Every section is built from the same six z-layers. The camera moves slightly with the pointer (or your hand), so the layers separate. When you scroll, the sheet explodes outward along z and the next one moves in.

L0 · terminal substrate
L1 · grid paper
L2 · display type
L3 · subject
L4 · notes
L5 · HUD
  1. L0Live terminal. Boot log, real commands, CRT shader (scanlines, slight barrel, phosphor glow). Always running, only visible through tears.
  2. L1Grid paper sheet with paper grain and a light normal map. Its torn edges are generated per section from noise.
  3. L2Display type as SDF text in WebGL, matched exactly to the HTML text beneath it. Can wave, explode and switch between outline and fill.
  4. L3The subject: your portrait, a project card fan, an exploded tech stack. The only layer with real 3D models.
  5. L4Sticky notes, tape, pins, handwritten notes. Physics-lite: they swing when the sheet moves.
  6. L5HUD in plain HTML. Breadcrumb path, command line, gesture camera preview. Never moves.

How it's built

Only the public site is rebuilt. The CMS dashboard, Supabase schema, auth and the data-fetching hooks stay. Two small additions: a subdomains table and a slug column on projects.

  • ShellReact 18 + Vite (kept). Static HTML per route generated at build time with vite-react-ssg.
  • 3Dthree + @react-three/fiber + drei. One fixed canvas, using drei View to tie 3D scenes to HTML elements.
  • ShadersCustom GLSL for tearing, CRT, halftone and ribbon. Postprocessing for bloom and chromatic aberration.
  • MotionLenis smooth scroll + GSAP ScrollTrigger as the single timeline. Framer Motion stays in the CMS only.
  • Hands@mediapipe/tasks-vision HandLandmarker, lazy-loaded, mapped to pointer events.
  • BudgetVisible content within 1.5s from static HTML. 3D chunk loads after first paint, under 250KB gzipped excluding models. Rendering pauses when the tab is hidden.

Why "dhanush karthik" doesn't find you

I checked the repo and the live site. Searching "dhanushkarthik" works because it matches your domain exactly. Searching "dhanush karthik" puts you up against everyone else with that common name, and your page gives Google weak signals that you are that person.

High

The visible heading is one word

The hero shows public class DhanushKarthik, so the biggest text on the page is the joined form. The spaced name appears only in the title and meta tags.

High

The HTML is empty until JavaScript runs

The live HTML has only an empty <div id="root">. Google indexes it in a delayed second pass, and Bing, LinkedIn and WhatsApp previews see nothing.

High

The OG image is broken

/og-image.png returns status 200, but it is your index.html, because of the SPA catch-all redirect. Shared links show no image.

Med

Weak identity markup

The Person JSON-LD has no @id, image or alternateName, and there is no WebSite or ProfilePage schema. The structured-data.json file is never loaded.

Med

Mixed domains

The README, the default email and contact use dhanushkarthik.dev, while the canonical is .com. Pick one and redirect the other.

Low

Only one URL to index

The sitemap lists only /, so there are no project pages and no subdomains for Google to show as sitelinks.

Fixes in the rebuild

  1. Make the <h1> read Dhanush Karthik with a space, in prerendered HTML. The Java line stays as decoration, hidden from screen readers.
  2. Title: Dhanush Karthik — Java Backend Engineer. Add a WebSite schema with name: "Dhanush Karthik" and alternateName: ["DhanushKarthik", "dhanushkarthik.com"]; this also controls the site name shown in results.
  3. One Person entity with @id: https://dhanushkarthik.com/#person, wrapped in ProfilePage, with image, sameAs (LinkedIn, GitHub, X) and knowsAbout. Use the exact same name on every profile.
  4. Generate real OG images at build time, one per page.
  5. One indexable page per project (/projects/:slug), and a sitemap with lastmod from the CMS.

Getting subdomains listed

  1. Verify a Domain property in Search Console. It covers *.dhanushkarthik.com in one place and lets the root sitemap list URLs on the subdomains.
  2. Link every subdomain from the main site with plain <a href> links (Network section and footer), and link each subdomain back to the main site.
  3. Each subdomain needs its own sitemap, no noindex, its own title, and a small JSON-LD block that points to the same #person @id as author.
  4. Google decides which sitelinks to show; we can't force them. Clear structure and links make them likely. Expect two to six weeks after the rebuild ships.
